────────────────────────────────────────────────────────────────────────────────
  2.1  Question  (absztrakt ősosztály)
────────────────────────────────────────────────────────────────────────────────

  FÁJL: question.h

  MIT CSINÁL:
    A két kérdéstípus közös alapja. Tartalmazza a kérdés szövegét,
    a kategóriát, a helyes választ és a 4 válaszlehetőséget.
    Mivel absztrakt, NEM lehet közvetlenül példányosítani.

  TAGVÁLTOZÓK (protected, hogy a leszármazottak is elérhessék):
  ───────────────────────────────────────────────────────────
  │ Név            │ Típus                    │ Leírás                          │
  ├────────────────┼──────────────────────────┼─────────────────────────────────┤
  │ question       │ std::string              │ Kérdés szövege                  │
  │ category       │ std::string              │ Kategória (pl. "Történelem")    │
  │ correctAnswer  │ std::string              │ Helyes válasz ("A".."D" vagy    │
  │                │                          │ "ABCD" típusú sorrend)          │
  │ answers        │ std::vector<std::string>  │ 4 válaszlehetőség szövege      │
  ───────────────────────────────────────────────────────────

  KONSTRUKTOR (protected):
    Question(const std::string& q,
             const std::string& cat,
             const std::string& correct,
             const std::vector<std::string>& ans)
      → Inicializálja mind a 4 tagváltozót.
      → Protected, mert a Question önmagában nem példányosítható;
        csak a leszármazottak hívhatják a saját konstruktorukból.

  VIRTUÁLIS DESTRUKTOR:
    virtual ~Question() = default;
      → Azért kell virtual, mert polimorf osztályhierarchiánk van.
        Ha Question* pointerrel töröljük a leszármazott objektumot,
        a helyes destruktor hívódik meg (nem lenne undefined behavior).
      → default, mert az std::string és std::vector automatikusan
        felszabadítják magukat (RAII).

  TISZTÁN VIRTUÁLIS METÓDUSOK (pure virtual):
    virtual void display() const = 0;
      → A kérdés konzolra írása. A ChooseQuestion és az OrderQuestion
        máshogy jeleníti meg magát (más fejléc, más formátum).
      → "= 0" → nincs törzse az ősosztályban → absztrakttá teszi.

    virtual bool checkAnswer(const std::string& input) const = 0;
      → Ellenőrzi, hogy a megadott válasz helyes-e.
      → ChooseQuestion: 1 betű egyezés ("A" == "A")
      → OrderQuestion:  4 betű egyezés ("ABCD" == "ABCD")

  GETTER METÓDUSOK (publikus, const, nem virtuális):
    const std::string& getQuestion() const;
    const std::string& getCategory() const;
    const std::string& getCorrectAnswer() const;
    const std::vector<std::string>& getAnswers() const;
      → Egyszerű hozzáférés a protected tagváltozókhoz.
      → const referenciát adnak vissza (nincs másolás).

  MIÉRT KELL VIRTUÁLIS?
    Mert a Game osztály Question* vagy Question& típuson keresztül is
    kezelheti a kérdéseket, és a helyes display()/checkAnswer() hívódjon.
    Bár a jelenlegi tervben a Game külön vector-okban tárolja a két típust,
    a virtuális felépítés lehetővé teszi a későbbi bővítést
    (pl. vector<unique_ptr<Question>> heterogén tároló).

  2.4  HighScoreEntry  (dicsőséglista egy bejegyzése)
────────────────────────────────────────────────────────────────────────────────

  FÁJL: highscore.h

  MIT CSINÁL:
    Egy játékos eredményét tárolja: név, nyeremény, dátum.
    A C verzió HighScore struct-jának C++ megfelelője.
    std::string-ek → nincs strdup/free.

  TAGVÁLTOZÓK (private):
  ───────────────────────────────────────────────────────────
  │ Név    │ Típus          │ Leírás                        │
  ├────────┼────────────────┼───────────────────────────────┤
  │ name   │ std::string    │ Játékos neve                  │
  │ prize  │ int            │ Elért nyeremény (Ft)          │
  │ date   │ std::string    │ Dátum, "ÉÉÉÉ/HH/NN"          │
  ───────────────────────────────────────────────────────────

  KONSTRUKTOR:
    HighScoreEntry(const std::string& name, int prize, const std::string& date)
      → Inicializálja a három mezőt.

  GETTEREK:
    const std::string& getName()  const;
    int                getPrize() const;
    const std::string& getDate()  const;

  OPERÁTOR (rendezéshez):
    bool operator>(const HighScoreEntry& other) const;
      → return prize > other.prize;
      → A dicsőséglista csökkenő sorrendű rendezéséhez kell.
      → Az std::sort()-tal használható:
          std::sort(entries.begin(), entries.end(),
                    [](const HighScoreEntry& a, const HighScoreEntry& b)
                    { return a > b; });
        Vagy std::greater<>()-tal, ha van operator>.

  2.5  HighScoreTable  (dicsőséglista kezelő)
────────────────────────────────────────────────────────────────────────────────

  FÁJL: highscore.h

  MIT CSINÁL:
    A dicsoseglista.csv fájl betöltése, bővítése, rendezése és
    formázott konzolra írása. A C-beli saveHighscore() és
    showHighscores() függvények osztályba szervezve.

  TAGVÁLTOZÓK (private):
  ───────────────────────────────────────────────────────────
  │ Név       │ Típus                           │ Leírás             │
  ├───────────┼─────────────────────────────────┼────────────────────┤
  │ entries   │ std::vector<HighScoreEntry>     │ Bejegyzések        │
  │ filename  │ std::string                     │ CSV fájl elérése   │
  ───────────────────────────────────────────────────────────

  KONSTRUKTOR:
    HighScoreTable(const std::string& filename = "dicsoseglista.csv")
      → Beállítja a fájlnevet.
      → NEM tölti be automatikusan (azt a load() csinálja).

  METÓDUSOK:
    void load();
      → Megnyitja a CSV-t olvasásra (std::ifstream).
      → Átugorja a fejlécsort.
      → Soronként beolvassa: name;prize;date
      → Pontosvessző-ellenőrzés: ha nem 2 db ';' van, kihagyja a sort.
      → Feltölti az entries vektort.
      → A C-beli showHighscores() beolvasó részének felel meg.

    void save() const;
      → Kiírja az egész listát a fájlba (std::ofstream, nem append).
      → Fejléc: "Név;Nyerémeny;Dátum\n"
      → Soronként: name;prize;date

    void add(const std::string& name, int prize);
      → Aktuális dátumot lekéri (localtime).
      → Formátum: "ÉÉÉÉ/HH/NN"
      → Létrehoz egy HighScoreEntry-t és push_back-kel hozzáadja.
      → Append módban hozzáírja a CSV végéhez (std::ofstream, ios::app).
      → A C-beli saveHighscore() függvénynek felel meg.
      → Ha a fájl üres/nem létezik, először fejlécet ír.

    void display() const;
      → Betölti a fájlt (load logika, vagy a már betöltött entries-t használja).
      → Rendezi csökkenő nyeremény szerint (std::sort + operator>).
      → Formázott kiírás:
          Játékos | Nyeremény | Dátum
          A nyereményt formatPrize()-zal formázza.
      → A C-beli showHighscores() kiíró részének felel meg.

  2.6  FileManager  (fájlkezelő, csak statikus metódusok)
────────────────────────────────────────────────────────────────────────────────

  FÁJL: filemanager.h, filemanager.cpp

  MIT CSINÁL:
    CSV fájlok beolvasása. Nincs állapota, nincs példánya → minden
    metódus static. A C-beli loadChooseQuestions() és
    loadOrderQuestions() függvények osztályba szervezve.

  TAGVÁLTOZÓ:
    Nincs. (Csak statikus metódusok, nem példányosítjuk.)

  KONSTRUKTOR:
    Nincs (vagy privát/delete-elt, hogy ne lehessen példányosítani).
      FileManager() = delete;

  STATIKUS METÓDUSOK:

    static std::vector<ChooseQuestion>
    loadChooseQuestions(const std::string& filename);
      → Megnyitja a CSV-t (std::ifstream).
      → Fejlécsor átugrása.
      → Soronként: pontosvesszők számlálása (7 db-ot vár).
      → Darabolás (std::getline + std::istringstream, vagy manuális

  3.6  Kérdés kiválasztási algoritmus
────────────────────────────────────────────────────────────────────────────────

  A Game::play() metódusban minden szinten a következő algoritmus fut:

  1. Meghatározzuk, hogy az adott szint sorrendezős-e:
       MODE_ORDER  → mindig true
       MODE_BOTH   → (currentLevel + 1) % 3 == 0  (3., 7., 11. szint)
       MODE_CHOOSE → mindig false

  2. Ha feleletválasztós:
       → chooseQuestions[currentLevel] vektorból véletlenszerű index
         (rand() % vector.size())
       → A kiválasztott ChooseQuestion referenciáját használjuk

  3. Ha sorrendezős:
       → orderQuestions vektorból véletlenszerű index
         (rand() % vector.size())
       → A kiválasztott OrderQuestion referenciáját használjuk

  4. A kérdés .display() metódusa kiírja a kérdést (polimorf hívás)

  5. Válasz bekérés → .checkAnswer() metódus ellenőriz (polimorf hívás)

  3.7  formatPrize algoritmus (Game::formatPrize)
────────────────────────────────────────────────────────────────────────────────

  CÉL: Egy egész számot (pl. 5000000) "5.000.000" formátumú stringgé alakítani.

  LÉPÉSEK:
    1. Az int-et std::to_string()-gel szöveggé alakítjuk: "5000000"
    2. Hátulról előre haladunk egy számlálóval.
    3. Minden 3. számjegy után egy '.' karaktert szúrunk be.
    4. Eredmény: "5.000.000"
    5. std::string-et adunk vissza (nincs malloc, nincs free).

  Ez a C-beli formatPrize() logikájának egyszerűsített C++ változata.
  Ott malloc + strdup + free kellett, itt automatikus.

────────────────────────────────────────────────────────────────────────────────
  3.8  CSV betöltési algoritmus (FileManager::loadChooseQuestions)
────────────────────────────────────────────────────────────────────────────────

  CÉL: A kerdesek.csv fájlból ChooseQuestion objektumok vektorát előállítani.

  LÉPÉSEK:
    1. std::ifstream megnyitás. Ha nem sikerül → üres vektor, hibaüzenet.
    2. Fejlécsor átugrása (std::getline).
    3. Soronként beolvasás (std::getline):
       a. Pontosvesszők számlálása: std::count(line.begin(), line.end(), ';')
          Ha nem 7 → continue (hibás sor kihagyása).
       b. std::istringstream + std::getline(ss, field, ';') darabolás:
          → 8 mező: nehézség, kérdés, A, B, C, D, válasz, kategória
       c. Nehézség: std::stoi() → 1..12 tartomány ellenőrzés.
          Ha kívül esik → continue.
       d. ChooseQuestion objektum létrehozása a kinyert mezőkből.
       e. push_back a visszatérési vektorba.
    4. A vektor visszaadása (move semantics → nincs másolás).

  A sorrendezős betöltés (loadOrderQuestions) ugyanez, de 6 pontosvesszővel
  és OrderQuestion objektumokkal.

────────────────────────────────────────────────────────────────────────────────
  3.9  Dicsőséglista rendezési algoritmus (HighScoreTable::display)
────────────────────────────────────────────────────────────────────────────────

  CÉL: A bejegyzéseket csökkenő nyeremény szerinti sorrendben kiírni.

  LÉPÉSEK:
    1. load() meghívása → entries vektor feltöltése a CSV-ből.
    2. std::sort() hívás csökkenő rendezéssel:
         std::sort(entries.begin(), entries.end(),
                   [](const HighScoreEntry& a, const HighScoreEntry& b)
                   { return a > b; });
       Az operator> az HighScoreEntry-ben a prize mezőt hasonlítja.
    3. Formázott kiírás: minden bejegyzésre Game::formatPrize().

  A C verzióban kézi selection sort volt (O(n²)), itt std::sort (O(n log n)).

  7. VIRTUÁLIS FÜGGVÉNYEK – MIÉRT ÉS HOL?
     (Az osztálydiagram öröklési hierarchiájának indoklása)
================================================================================

  A Question osztályban 3 virtuális függvény van:

  1) virtual ~Question() = default;
     → VIRTUÁLIS DESTRUKTOR
     → Szükséges, ha valaha Question* pointerrel törlünk egy
       leszármazott objektumot. Enélkül undefined behavior lenne.
     → Bár a jelenlegi tervben nem használunk Question* heterogén
       tárolót, az osztályhierarchia jó gyakorlata megköveteli.

  2) virtual void display() const = 0;
     → TISZTÁN VIRTUÁLIS (pure virtual)
     → Nincs törzse az ősben → Question absztrakt osztály lesz.
     → ChooseQuestion::display() → "Téma: ... " formátumban írja ki.
     → OrderQuestion::display() → "[SORRENDEZŐS] Téma: ..." formátumban.
     → Polimorfizmus: ha Question& ref-en keresztül hívjuk, a
       helyes leszármazott display()-e fut le.

  3) virtual bool checkAnswer(const std::string& input) const = 0;
     → TISZTÁN VIRTUÁLIS (pure virtual)
     → ChooseQuestion: input == correctAnswer (1 betű: "A")
     → OrderQuestion: input == correctAnswer (4 betű: "ABCD")
     → Polimorfizmus: ugyanaz az interfész, más a belső logika.

  HOL VAN OVERRIDE?
     → A leszármazottakban minden felülírt függvénynél "override"
       kulcsszót használunk. Ez fordítási idejű ellenőrzést ad:
       ha elgépeljük a függvény nevét vagy a paramétereket,
       a fordító hibát jelez.

  MIÉRT NEM VIRTUÁLIS A TÖBBI METÓDUS?
     → getQuestion(), getCategory() stb. → minden leszármazottban
       ugyanúgy működnek, nincs szükség felülírásra.
     → Game metódusai → a Game nem része az öröklési hierarchiának.

  8. STATIKUS TAGOK – MIÉRT ÉS HOL?
     (Az osztálydiagram static jelölésű elemeinek indoklása)
================================================================================

  Game osztályban:
    static const int LEVELS = 12;
    static const int PRIZE_LADDER[LEVELS];
      → Ezek az osztály ÖSSZES példányára azonosak.
      → Nem változnak futás közben → const.
      → static → nem foglalnak helyet minden Game objektumban,
        hanem egyetlen példányban léteznek.
      → A C-beli #define LEVELS és static const int PRIZE_LADDER[]
        megfelelői.

    static std::string formatPrize(int prize);
    static bool isSafeLevel(int index);
    static int  getSafePrize(int index);
    static void printSeparator();
    static void waitEnter();
      → Ezek NEM használják a Game objektum állapotát (tagváltozóit).
      → Bármikor meghívhatók Game példány nélkül is:
          Game::formatPrize(5000000)  → "5.000.000"
          Game::isSafeLevel(4)        → true
      → A C-beli szabad (globális) segédfüggvények osztályba szervezve.

  FileManager osztályban:
    static vector<ChooseQuestion> loadChooseQuestions(filename);
    static vector<OrderQuestion>  loadOrderQuestions(filename);
    static bool fileExists(path);
      → A FileManager-nek nincs állapota, nincs tagváltozója.
      → Minden metódusa static → nem kell példányosítani.
      → A konstruktor delete-elve van, hogy ne lehessen létrehozni.
      → Alternatíva lenne namespace-ként megvalósítani, de az
        osztály-forma jobban illeszkedik az OOP tervhez.

  10. HIBAKEZELÉS
================================================================================

  A hibakezelési stratégia megegyezik a C verzióval, de C++ eszközökkel:

  - Fájl megnyitási hiba:
      std::ifstream megnyitás, if (!file.is_open()) → hibaüzenet, return.
      NEM dobunk kivételt (a spec nem követeli meg).

  - Hibás CSV sor:
      Pontosvesszők számlálása: std::count(line.begin(), line.end(), ';')
      Ha nem a várt szám → continue (sor kihagyása).

  - Üres fájl / hiányzó fejléc:
      Ha az első std::getline() false-t ad → hibaüzenet, return.

  - Érvénytelen nehézségi szint:
      std::stoi() + tartomány-ellenőrzés (1..12 közötti).
      Ha kívül esik → continue (sor kihagyása).
      std::stoi() std::invalid_argument kivételt dobhat → try-catch.

  - Üres játékosnév:
      if (name.empty()) name = "Jatekos";

  - ';' a névben:
      std::replace(name.begin(), name.end(), ';', ' ');
      CSV injection védelem.

  - Érvénytelen válasz:
      Ciklusban bekérjük amíg érvényes nem lesz.

  - 50:50-vel kizárt válasz:
      Ellenőrizzük a hiddenResponses tömbbel, figyelmeztetés + újra bekérés.

  11. TESZTELÉSI TERV
================================================================================

  - CSV betöltés tesztek:
      - Üres fájl → 0 kérdés, nincs crash
      - Hibás sor (kevés/sok ';') → kihagyva, többi rendben
      - Érvénytelen nehézség (0, 13, -1) → kihagyva
      - Normál fájl → helyes darabszám szintenként

  - Játéklogika tesztek:
      - Game::isSafeLevel(4) == true
      - Game::isSafeLevel(3) == false
      - Game::getSafePrize(3) == 0
      - Game::getSafePrize(4) == 100000
      - Game::getSafePrize(9) == 1500000
      - Game::formatPrize(5000000) == "5.000.000"
      - Game::formatPrize(0) == "0"

  - Kérdés tesztek:
      - ChooseQuestion::checkAnswer("A") == true (ha correct == "A")
      - ChooseQuestion::checkAnswer("B") == false (ha correct == "A")
      - OrderQuestion::checkAnswer("ABCD") == true (ha correct == "ABCD")
      - OrderQuestion::checkAnswer("ABDC") == false (ha correct == "ABCD")

  - Válasz érvényesítés:
      - Feleletválasztós: "A","B","C","D" érvényes, "E","AB","" érvénytelen
      - Sorrendezős: "ABCD" érvényes, "ABC","ABCE","" érvénytelen
      - 50:50 után kizárt válasz → elutasítva

  - Dicsőséglista:
      - Üres fájl → fejléc automatikusan létrejön
      - Mentés után visszaolvasás → egyezik
      - Rendezés csökkenő → helyes sorrend

  - Segítségek:
      - 50:50: pontosan 2 rossz választ rejt el, helyes marad
      - Közönség: összesen 100%, helyes válasz >= 30%
